DMGT Unit 2: Mathematical Relations & Partial Ordering (Posets)

Formal Poset Hasse Diagram & Equivalence Partitioning

Proving that the SaaS escalation hierarchy represents a strict partially ordered set (Poset) and category equivalence classes.

Poset Relation (S, ⪯) Axioms

1. Reflexivity Satisfied
∀ a ∈ S : a ⪯ a

Every support agent has equal authority to triage within their own tier boundary.

2. Antisymmetry Satisfied
∀ a, b ∈ S : (a ⪯ b ∧ b ⪯ a) ⇒ a = b

No circular escalation is permitted. L1 cannot escalate down to L2 while L2 escalates down to L1.

3. Transitivity Satisfied
∀ a, b, c ∈ S : (a ⪯ b ∧ b ⪯ c) ⇒ a ⪯ c

Authority propagates forward: if L1 ⪯ L2 and L2 ⪯ L3, then L3 can resolve any ticket initiated at L1.

Equivalence Relation Partitioning

Let R be a relation on ticket set T such that t₁ R t₂ ⇔ Category(t₁) = Category(t₂).

public abstract class BaseSupportAgent {
    protected String agentId;
    protected String tierName;
    protected int authorityLevel;

    public abstract ResolutionResult resolveTicket(Ticket ticket);
}

// Polymorphic Subclass 1: Technical & Database Issues
public class DevOpsSpecialist extends BaseSupportAgent {
    @Override
    public ResolutionResult resolveTicket(Ticket ticket) {
        DatabaseConnectionPool.drainAndReclaim(ticket.getContext());
        return new ResolutionResult("RESOLVED_INFRA_AUTO_REMEDIATED", 12);
    }
}

// Polymorphic Subclass 2: Invoicing & Subscription Issues
public class BillingSpecialist extends BaseSupportAgent {
    @Override
    public ResolutionResult resolveTicket(Ticket ticket) {
        StripeGateway.reconcileCustomerInvoice(ticket.getCustomerId());
        return new ResolutionResult("RESOLVED_INVOICE_ISSUED", 8);
    }
}
